# warden-gitops

Desired state of every Warden cluster. **Argo CD is the only thing that applies it**; nothing in CI has cluster
credentials. Design: hub `DESIGN.md` §8; decisions ADR-013, ADR-014.

```
bootstrap/
  root-local.yaml    applied once by `task up:local` (warden-infra)
  root-azure.yaml    applied once by `task up:azure`
clusters/
  local/             kind: Applications + overlays (NodePort gateway, CNPG default composition, lite profile)
  azure/             AKS: Applications + overlays (LoadBalancer gateway, Azure DB composition)
platform/            one Argo CD Application (+ values) per component, Helm chart versions from the hub's versions.yaml
  argo-rollouts/ kyverno/ envoy-gateway/ observability/ crossplane/ cnpg/ k6/
apps/<svc>/          generated by `warden new`; the image digest is changed only by bot PRs
.github/             digest-only guard (required status check)
```

## How changes arrive

| Change | Path | Merge rule |
|--------|------|-----------|
| New service | `warden new` opens a PR adding `apps/<svc>/` | human review |
| New image digest | promotion bot PR touching one line in `apps/<svc>/rollout.yaml` | `digest-only` check green → auto-merge |
| Platform upgrade | PR bumping a chart version (Renovate or human) | human review |
| Policy change | **not here** — `warden-policy` repo; this repo only points at it | — |

## Rulesets (set up in week 1)

1. `main` requires a PR with 1 approval — bypass list: the `warden-promoter` GitHub App only.
2. `main` requires status check `digest-only` — **no** bypass.

Sync waves: CRDs/operators `0` → policies `1` → observability `2` → gateway `3` → apps `10`.
